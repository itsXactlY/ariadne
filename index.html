The tools — wired in, all real

Every tool the model can call is registered live: the core four ship compiled-in; the remaining 34 are discovered at startup from the mazemaker pod through MCP tools/list, each with its real inputSchema. The server's initialize instructions — the MAZEMAKER MEMORY PROTOCOL (recall-first, persist-after-turn) — are appended to agent.system_prompt. That is what makes recall-first behavior real, not simulated.

Core four — compiled in, real filesystem I/O

write_file
Write text content to a file.
write_file("out.txt", content="...")
list_dir
List entries of a directory.
list_dir("/tmp") → "drwxr-xr-x … 14 entries"
run_terminal
Run a shell command — everything allowed except a denylist (sudo, su, recursive rm on /·~·*, mkfs, dd, shutdown/reboot, curl-pipe-shell, force-push, …; extra words via config command_denylist). Runs { cmd; } </dev/null 2>&1 so a child never reads the raw-mode tty. It is a guard, not a jail — do not treat it as sandboxing.
returns exit code + stdout

The mazemaker pod — 34 live MCP tools (registered at startup)

mazemaker_recall
Semantic search over the persistent memory graph — hybrid recall (semantic + FTS + ColBERT + DAE + salience channels) with a recency channel. The recall-first protocol anchor.
mazemaker_recall_advanced
Same shape, per-call channel tuning: ColBERT/DAE weights, temporal weight, MMR diversity, score-percentile filter, retrieval mode. A debugging tool, not the hot path.
mazemaker_recall_multi
Two-to-five phrasings in parallel, fused via Reciprocal Rank Fusion — for when one phrasing misses a stored fact.
mazemaker_get
Primary-key lookup by memory_id; on miss it returns nearest ids above/below so the agent can offer "did you mean X?" instead of hallucinating.
mazemaker_think
Spreading-activation graph traversal from a memory (depth 1–5) — concepts connected by the graph, not just by cosine.
mazemaker_remember
Persist a curated fact / decision / bug / invariant / ops / user / status memory. One memory per discrete fact, 60–300 words.
mazemaker_browse · stats · graph · health
Chronological browse (created_at DESC, optional label prefix), graph overview, corpus + AFE + dream + DAE health blob.
mazemaker_dream · nrem · rem · insight · supersedes
The dream cycle: NREM replay + edge strengthening, REM bridge discovery between isolated memories, Louvain communities + cluster summaries, cross-session conflict marking via SUPERSEDES.
mazemaker_dream_afe · synthesize · rebake · afe_facts · synth_lineage
AFE atomic-fact extraction (markdown → NER → LLM user-state), Stage S crystallisation (~10% yield by design), query-conditional Stage C rebake on missed sessions. Pro tier; Community calls return structured "skipped" payloads.
mazemaker_prune · dream_control · dream_config · delete_by_labels · count/list_by_label_prefix
Edge pruning with age protection + dry-run preview; dream daemon pause/resume/status; cadence knobs; FK-safe label deletion and uncapped namespace walks.
mazemaker_classify_intent · ablate · diagnose · supersedes_log · get_by_prefix
Cheap regex intent routing (preference / temporal / factual / general), channel-ablation matrix, typed-miss diagnostics on the live corpus.

Full harness kit — build/dd_tui

make build/dd_tui
build/dd_tui                                   # interactive REPL (you> ), config from ~/.daedalus
build/dd_tui path/to/config.yaml -- "msg"      # single-shot

Same run loop (Agent::run) as dd_agent — no fork of the loop, one step_hook added to agent.hpp/.cpp for per-step streaming. Next-gen OOP TUI (dd::ui: double-buffered cell-diff Frame + Widget subclasses + Scene row layout):

  • Fixed geometry: transcript panel | 34-col sidebar (session, engine, tools) over a 3-row prompt box and a status row; rounded panels with titles set into the border; sidebar drops under 100 cols; under 60×14 the screen says so.
  • Cards: user = gold bar · answer = rounded ⟁ DAEDALUS ⟁ box with the call latency · tool = square card of fixed height (name, status queued/spinner/✓ 1.2s/✗, flattened args, two-line result preview) · notes, errors, and a rule closing each turn (turn 3 · 4 calls · 2 tools · 41.2s).
  • Skins: colours, spinner wings, thinking verbs and branding from ~/.daedalus/skins/<display.skin>.yaml (neural defaults built in). Truecolor when COLORTERM=truecolor|24bit, else xterm-256.
  • Engine stats are real: per-call llama-server timings (gen/prefill t/s, cache_n) and usage; n_ctx from /props once at start (the ctx meter).
  • Render: Canvas (16-byte padding-free Cell, wide-glyph aware) → Frame::present() diffs against the last frame and emits only changed cells, inside synchronized output (?2026) on the alternate screen. An unchanged frame writes nothing.
  • Threads, no locks: worker and tool threads only push events into a Vyukov MPSC queue (one atomic exchange); the render thread owns every bit of scene state and drains the queue each frame. interrupt_requested is std::atomic<bool> and doubles as the libcurl abort flag — Esc cancels an LLM call in flight (measured 0.86 s from Esc to ready during a live generation).
  • SIMD + OpenMP (dd/ui_simd.hpp): cell diff, ASCII scan/width/widen as AVX-512 (F+BW+VL) / AVX2 / scalar kernels, picked once by CPUID — one binary for every box. Rows encode in parallel on big frames, cards re-wrap in parallel after a resize; small frames stay serial so the TUI never wakes threads on cores the model uses. tests/ui_test.cpp checks each kernel set the CPU has against scalar, and 1-thread vs 8-thread frames byte for byte. (AVX-512 set hasn't run on hardware yet — Zen 2 here, QEMU TCG has none.)
  • Input: raw termios (restored on exit and fatal signals), CSI/SS3 keys, bracketed paste, SGR mouse wheel (DD_TUI_MOUSE=0 leaves the mouse to the terminal), UTF-8 line editing, history. Enter sends (while busy: queued for end of turn), Esc/Ctrl-C interrupt, PgUp/PgDn or wheel scroll, Tab completes /help /tools /turns N /clear /interrupt /quit, Ctrl-L redraws. stderr goes to ~/.daedalus/logs/dd_tui.log while the screen is up.
  • No tty (-- msg or piped stdin): the same cards print inline, in order.

Verified smoke (DD_MAX_TURNS=4, local IQ1 model ≈17 s/turn + ≈22 s/recall): registers 34 mazemaker tools, the model answers "as required by the memory protocol", issues mazemaker_recall, and the round-trip returns live memory (top hit sim 0.54). Transport lives in src/tools/mcp.hpp / src/tools/mcp_client.cpp.

Gotchas that bit once

libcurl 8.16+ calls the write callback with four args — fn(char*, size_t, size_t nitems, void*) (curl.h:285), not the classic three. A 3-param sink reads nitems (a byte count) as the userptr → SIGSEGV. Correct form appends nitems and returns it:

static std::size_t curl_sink(char* buffer, std::size_t size, std::size_t nitems, void* ud) {
    auto* s = static_cast<std::string*>(ud);
    s->append(buffer, nitems);
    return nitems;                       // return != nitems => CURLE_WRITE_ERROR
}
  • CMake is 4.4.3 and broken here. The Makefile is the source of truth; a CMakeLists.txt exists but is not the working path.
  • -Werror=unused-function is strict: every non-inline static helper must be referenced in its TU. Prefer inline/constexpr.
  • std::regex here gets no lookaround; \w/\d are ASCII-only.
  • core::Json is a hand-rolled value type (Type{Null,Bool,Num,Str,Arr,Obj}, JsonSP = shared_ptr<Json>): init-lists take JsonSP (wrap with jsp(...)), arr_push/obj_set take a bare Json, read size before a move. Wire finish_reason is a sibling of message on choices[0].

The whole deal — context tape

  1. Seed. One plain goal: a running int main() agent driving the already-ported run loop against the real llama.cpp endpoint — libcurl transport + real FS tools.
  2. Ported base, not rewritten. Run loop, core::Message, core::Json, tool registry were already green (64 suites). Only the missing leaves got written: HTTP transport, FS handlers, entrypoint.
  3. Scale. Long evolution, heavy tool churn, one hard crash (the libcurl 4-arg callback SIGSEGV) burned most of the tokens — then the 4-param sink fix, a clean -Werror rebuild, live smoke.
  4. Proof of concept. Working binary + documented gotchas + verified smoke = the PoC baseline. Everything open now builds on top of it without disturbing it.
